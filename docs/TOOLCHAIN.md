# Toolchain and verification boundaries

Python 3.12 runs in this repository's ignored `.venv`. The runner is pinned in
the ASCII contract header and resolves the v0.3 SDK from GenVM v0.6.0-rc8.
Install `requirements.txt`, then run `scripts/linter_v03_compat.py`.

The pinned official linter commit validates the v0.3 schema but its AST tables
omit `gl.vm.run_nondet_default` and `gl.storage.allow`. The compatibility script
adds only those exact verified names. It also adds the sandbox name to the
nested-sandbox prohibition. Five tooling regressions prove correct recognition
and continued rejection of unscoped nondeterminism, nested sandboxes, storage
writes in sandboxes and fake decorators. No diagnostic is suppressed.

Direct-test accommodations in `tests/direct/conftest.py` defer Windows stdin
file removal until the VM closes it and synchronize `warp` to v0.3
`gl.message.raw["datetime"]`. Address arguments use the actual SDK `Address`
type. The v0.30 mock transport decodes JSON once; test mocks preserve JSON text
for the v0.3 SDK's own decoder. None of these changes replaces contract logic.

Direct mode runs the leader and explicitly replays captured validators. It
does not run a GenVM sandbox or network consensus. Withdrawal tests observe the
real SDK's `EmitExternalMessage`, including exact recipient and prior credit
debit; they do not prove a native transfer. Actual Studio Dev smoke, finalized
lifecycle, native balance decrease and browser-wallet evidence remain pending.

The direct loader had a truncated cached rc8 archive. The incomplete file was
retained with an `.incomplete-20261006` suffix and replaced by the complete
official bundle already used by the schema validator. No project runner changed.

Local `gltest` integration runs five GLSim validators through the real fluent
client API. `scripts/local_sim.py` adapts the simulator's old method dispatch
key to genlayer-py's canonical empty-string key and feeds the exactly decoded
transaction value into its VM. An external-message observer acknowledges only
bounded test emissions; GLSim native balance/transfer semantics are not claimed.
Live web/model fallback is disabled and installed mocks are asserted before
the first transaction. Ephemeral signers exist in memory only and every helper
rejects an RPC outside loopback port 4187. This is local consensus simulation,
not GenVM sandbox, Studio Dev finality or native GEN transfer proof.

The cold GLSim dispatch also needed conversion from client CalldataAddress to
the real loaded SDK Address while preserving the exact bytes. Its schema cache
retained types from a torn-down VM; the local server now uses the separate
SDK/linter-generated ABI and rejects any different source. These adaptations
affect only local tool fidelity. The SDK ABI is regenerated by `npm run check`.

Receipt parsing follows the raw Studio and normalized genlayer-js rc commit
672631bfff0a21a25d95591a523497f7c46fd01d shapes. It keeps lifecycle and execution
separate, rejects contradictory results, and projects no config/log payloads.

The shared legacy wallet canary was run against this installed RC SDK. It
normalized the account, but its old fixtures omitted receipt/block RPCs and
its assertions expected the old positional consensus ABI. The bounded run was
stopped with exit 1; it is not passing evidence. The project-owned
`tests/tooling/sdk-wallet-preflight.test.mjs` uses the current Studio Dev chain,
fee-aware tuple ABI and offline EVM-inclusion receipt. It proves zero/1 GEN,
account normalization, and no signing/broadcast outside the intercepted provider.
Current SDK destination validation can perform a nonce read before rejecting an
undefined destination; the project adapter therefore validates configuration
before calling the SDK. The invalid-address regression proves no I/O at that
project boundary, rather than asserting behavior the vendor no longer provides.
Actual project-adapter regressions additionally cover all nine writes, exact
2-GEN purchases, selected-provider routing, chain switching, changed accounts,
latest-final reads, pending confirmation and no duplicate broadcast.

The bounded Studio Dev constructor simulation found a header-order defect that
local lint did not detect: Depends first and version second returned
`invalid_contract runner malformed`. The current target template requires
`# v0.3.0` first, then the exact Depends comment. Reordering only those two
lines in memory returned SUCCESS with measured fee accounting and no network
write. The metadata regression was corrected (observed RED), then source order
was fixed without changing runner, API, contract count or business logic.
Deployment simulation supplies the SDK baseline fee distribution before
measuring its exact GenVM execution; no gasless behavior is assumed.
